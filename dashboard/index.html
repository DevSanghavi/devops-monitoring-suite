2. Alarm rules (Amazon CloudWatch)

Alarms watch the server around the clock. When one triggers, CloudWatch sends an email through Amazon SNS. Live graphs are in the CloudWatch console; this page shows the rules.

CPU usageHow busy the processor is. Built-in EC2 metric.Average is above 70 percent for two checks in a row (5 minutes each)A busy CPU makes the APIs slow or time out.

3. Automation running on the server

Four background jobs keep the server observable and recoverable without manual work.

Metrics collection EVERY 60 SEC

The CloudWatch Agent reads memory and disk usage and publishes them to CloudWatch in the DevOpsMonitoring namespace. These are the numbers the memory and disk alarms use.

Daily log backup DAILY 23:45 UTC

A systemd timer starts a backup script. It compresses the last 24 hours of container logs and uploads them to a private, encrypted, versioned S3 bucket in a time-stamped folder. The server can upload backups but cannot delete them.

Log rotation DAILY

logrotate keeps 7 compressed copies of each container log (rotating early at 50 MB) and of the backup log (10 MB). This stops logs from filling the disk.

Central logs 7 DAYS

The staging and production API containers stream their logs to CloudWatch Logs, which keeps them for 7 days. Problems can be investigated without logging in to the server.
